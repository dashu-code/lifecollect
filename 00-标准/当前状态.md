## 一、现在能做什么（都实测过）

### 1. 建一个加密档案

```powershell
pip install -r requirements.txt        # 唯一依赖：cryptography
python -m lifecollect init --root "D:\我的档案" --security-level standard --subject "张三"
```

三个安全级别由用户选，但界面必须同时显示"挡什么"和"**不挡什么**"：

| 级别 | 密钥保护 | 挡什么 | 不挡什么 |
|---|---|---|---|
| `basic` | 无 | 顺手翻看、误删 | 拿到文件的人。**等于没有加密保护** |
| `standard` | DPAPI + 口令 | 磁盘被单独拿走 | 能接触已解锁机器的人 |
| `paranoid` | 仅口令 | 上述 + 离线暴力破解 | **密钥丢失即永久不可读** |

### 2. 导入材料

12 种扩展名：`.csv .tsv .jsonl .ndjson .json .html .htm .xhtml .txt .log .md .text`

自动编码探测（UTF-8 / BOM / GB18030 / UTF-16）、列名识别、目录导入登记媒体、重跑幂等。
**不猜发送者**：不传 `--self` 时方向标 `unknown`。

### 3. 标注内容类型

7 类，每条带判定规则 + 置信度。没命中规则的标 `unknown`，不硬塞。

### 4. 检索

中文单字、双字、多字、跨词边界；中英混排；全角半角等价。
检索层**整个删掉能重建**。

### 5. 出人类可读清单

4 份 Markdown，其中一份专门**列出档案的毛病**（多少条没时间、多少条标注不确定、
多少条含第三方隐私、高价值材料够不够门槛）。

### 6. 加密（本轮新增）

```powershell
python -m lifecollect lock   --root "D:\档案"   # 加密
python -m lifecollect status --root "D:\档案"   # 不需要口令
python -m lifecollect verify --root "D:\档案"   # 校验
python -m lifecollect unlock --root "D:\档案"   # 解密
python -m lifecollect passwd --root "D:\档案"   # 换口令（只重包密钥，不重加密档案）
```

| 项 | 选择 |
|---|---|
| 对称加密 | AES-256-GCM（认证加密，改一个字节必须失败） |
| 密码派生 | scrypt n=2^14 r=8 p=1（实测约 190ms） |
| 每文件子密钥 | HMAC-SHA256(主密钥, 路径) |
| 块认证 | 路径 + 块序号进 AAD（防调换、防搬移） |

**文件格式**：明文 JSON 头 + 若干 `nonce+密文+tag` 块。
头部故意不加密——二十年后没有这个程序也能照着它解开。

**永远明文的**（设计约束，不是遗漏）：`00-说明.md`、`01-授权/`、`90-审计/`、
`密钥信封.json`、`加密清单.json`、`_meta.json`。

> `90-审计/` 明文的原因：锁操作本身要写日志。加密它会导致
> 「加密 → 写日志 → 新明文」永不收敛。代价是日志泄露"有哪些操作发生过"，
> 不泄露"内容是什么"。

### 7. 三条不可违背的顺序

1. **先验证再删原文**：加密 → 解一遍验证 → 逐字节一致 → 才删明文
2. **解锁默认保留密文**，删密文要显式 `--remove-ciphertext`
3. **换口令只重新包裹主密钥**，不重新加密档案

## 二、现在不能做什么

| # | 缺什么 | 后果 | 严重度 |
|---|---|---|---|
| 1 | **没有界面** | 只有命令行，非技术用户用不了 | **高** |
| 2 | **微信数据库直读没做** | 只能导已导出的文件，不能直接从微信取 | 高 |
| 3 | 秘密共享的密钥托管没实现 | 方案倾向 A，但代码没写 | 中 |
| 4 | 语音转码没做 | SILK 只登记不解码，本机没装 ffmpeg | 中 |
| 5 | 照片 EXIF 时间线没做 | 照片时间读不到 | 低 |
| 6 | 会话标题不进索引 | 搜文件名搜不到 | 低 |

## 三、验证情况

| 项 | 结果 |
|---|---|
| 采集链路测试 | **50 个全过** |
| 加密测试 | **53 个全过**（一半在测"不该成功时必须失败"） |
| 一次跑全部 | `python -m unittest discover -p "*test.py"` → **103 个，OK** |
| 端到端演示 | `python demo_crypto.py`，含篡改检测、错误口令拒绝 |
| 第三方依赖 | **1 个**：cryptography（AES-GCM 不能自己写） |

加密测试里专门验证的"必须失败"场景：

- 密文改任意一个字节 → 必须被发现（逐字节 × 3 种掩码全测）
- 同一明文两次加密 → 密文必须不同（nonce 随机化）
- A 文件的密文当作 B 文件解 → 必须失败（路径进 AAD）
- 密文块调换顺序 / 删掉一块 / 截断 → 必须全部失败
- 错误口令 / 错误密钥 / 指纹不符 → 必须拒绝
- 篡改后 `verify` 退出码必须非 0

## 四、离"能给别人用"还差什么

**只剩两件，而且有先后：**

**1. 桌面界面（pywebview）**

加密已经完成，现在可以安全地套 UI 了。
之前之所以说"先加密再界面"，是因为界面会让用户以为有保护——
现在这个前提成立了。

**2. 微信直读（级别 1 来源）**

有硬障碍：读微信进程内存会被杀毒软件拦。**大多数非技术用户会死在这一步**，
所以必须有降级路径和明确提示，不能假装它总是能用。
